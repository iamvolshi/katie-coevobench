KATIE on CoEvoBench

A tiny proof of concept, not a robust demo. It shows the break, then the fix.

Paper: CoEvoBench, arXiv:2611.27116. Code and full report: iamvolshi/katie-coevobench.

Read this first. This is a simulation of the Figure 5 case, not a real AppWorld run and not real training. No model was trained, no AppWorld tasks were run. The numbers come from constants typed from the paper, plus 5, minus 4, plus 4, and Base 14 is an assumption, because the paper case gives only deltas. What this proves is that the record and the gate work as designed. It does not prove KATIE helps a real researcher. A real run still needs Docker, 4 GPUs, and a teacher model budget.

Live judge, held-out

Nemotron 3.5 Bolt E4B, NVIDIA free tier, Nov 24, OCME-009-evo. On held-out set 5, ten changes the judge had never seen, it got 30 out of 30 after the backstop, 24 out of 30 from the model alone, 3 calls on each change. The 30 calls took 33.7 seconds, 1.1 seconds a call. K3 took about 1,770 seconds for its 30 calls on set 4, about 59 seconds a call. Same score, about 50 times faster. The hypermodel is not needed here.

  • Partial, H5-A3 and H5-A4: expected partial, got partial, 3 times each. The model said ambiguous all 6 times, the backstop named them partial.
  • Noise, H5-N1, H5-N2, H5-N3: expected noise, got noise, 3 times each. Full coverage noise still comes back noise.
  • Logical, H5-L1, H5-L2, H5-L3: expected logical, got logical, 3 times each.
  • Ambiguous, H5-A1 and H5-A2: expected ambiguous, got ambiguous, 3 times each.

The full live pipeline, 11 runs, ended equal to Control in all of them, skipped 1 job each, no job hurt.

Kimi K3.1 Pro, NVIDIA free tier, Nov 24, OCME-008-evo. On held-out set 4, ten changes the judge had never seen, it got 30 out of 30 after the backstop, 24 out of 30 from the model alone, 3 calls on each change.

  • Partial, H4-A3 and H4-A4: expected partial, got partial, 3 times each. The model said ambiguous all 6 times, the backstop named them partial.
  • Noise, H4-N1, H4-N2, H4-N3: expected noise, got noise, 3 times each. Full coverage noise still comes back noise.
  • Logical, H4-L1, H4-L2, H4-L3: expected logical, got logical, 3 times each.
  • Ambiguous, H4-A1 and H4-A2: expected ambiguous, got ambiguous, 3 times each.

The full live pipeline, 11 runs, ended equal to Control in all of them, skipped 1 job each, no job hurt. On the partial case that used to break, KATIE now ends at 18 against Control's 18. On set 3 it was 14 against 18.

Partial is a kind, alongside noise, logical, and ambiguous. A partial judgment holds, it does not train. The rule is in the backstop code and in one prompt line: if the coverage is partial, one touched example and one untouched example, say partial, not noise.

Honest limit: this is still a simulation, not a real AppWorld run and not real training. Held-out sets 1 to 5 were written by Turdy, not by the prompt builder, and sealed before the first call, so the 30 out of 30 is a held-out score. The prompt was tuned on the earlier scripts, and the set 1 to 3 freeze checks now read the code as it stood at each seal. Bolt and K3 never ran on the same set, so the two 30 out of 30 scores are not a same-set comparison. The timing for Bolt is Kiro's reported number, 33.7 seconds for 30 calls, not re-added from per-call times in the results file. Next: the paper itself, and Test 2, the second-round gain.

Before the ERIE fix, the old prompt got 2 out of 3 right and called the ambiguous change logical instead of holding. That miss is what the ERIE evidence packet fixed.

What this is, in plain words

CoEvoBench shows a researcher can make a strong first improvement, but cannot turn feedback from an improved system into the next one. Every harness revision reopens the training decision. KATIE is a record around the researcher loop. Every trajectory, harness change, and training job gets its own KID. Training data is gated by harness KID, so stale data is refused, stale weights are not served, and a bad job is skipped.
